实验 A1：仅由分割掩码生成中心线的辅助监督
状态：代码准备与 CPU 检查；尚无新训练成绩，不替换 v2。

规则修正
团队原草案使用 JSON 人工 spine 字段。2026-10-27 读取官方 Evaluation 的原文为：
“the models may not use any other ground-truth metadata for training.”
https://www.kaggle.com/competitions/filament-segmentation-2026/overview/evaluation
本实验据此不使用人工 spine、bbox、area 或 category 标签，只从允许的 segmentation 多边形计算辅助目标。除非组织方另有明确澄清，不启用人工 spine 版本。

假设与实现
共享 U-Net 编码器/解码器，同时学习前景掩码和细丝中心结构，有机会减少断裂与漏检。
输入、编码器、日期分折、训练种子、增强、优化器、50 epoch、batch 4 与 v2 相同。
在 1536 分辨率分别栅格化每个实例的分割多边形，Zhang skeletonization 后向外扩 1 像素并限制在原实例内。同一专家的各实例取并集，再平均专家，保留软标签。
掩码和中心线共用同一几何增强。损失为原 v2 掩码损失 + 0.25 × 中心线 BCE/soft-Dice；0.25 固定，不事后挑选。
模型增加第二输出通道。验证、TTA、最终预测只使用第零掩码通道，后处理保持 v2。
图像、掩码与辅助目标均留在主机内存，每个 batch 搬入 GPU；首轮实测表明 A1 不能再沿用 v2 的全数据 GPU 缓存。此调整不改变 batch、样本顺序、数值精度或损失。
这是辅助监督实验，不是新实例分割器，也不保证能区分所有粘连细丝。

对照与通过标准
先跑第 0、1 折。使用已存在的 Kaggle T4 v2 对照概率图，在同一固定评分器/后处理下重算两组；不为此重新训练同一基线。
不得直接混用其他机器记录的 0.4432 和旧评分器记录的 0.442872。先锁定同一评估实现与对照结果。
必须两折各自改善，合计 PQ 至少 +0.005，才考虑补第 2、3、4 折。五折阶段至少四折改善。
同步记录被拆分/被合并、完全漏检与 FP，但不据此事后改变主要通过标准。
没通过则保留 v2，不反复扫辅助权重制造“最好一次”。

运行与交付
python src/train_seg.py --config configs/A1.json --out runs/A1_t4
A1 默认不生成测试图预测。验证输出、权重、完整训练日志走团队共享产物目录；只将源码、配置、测试和结果摘要提交 Git。
模型加载器支持原单通道和双通道权重，预测始终只取掩码通道。
scikit-image 只用于训练目标预处理；选用成熟骨架实现，避免自行编写和调试细化算法。
首次 GPU 运行前：核实真实剩余额度、没有重叠作业，并预留至多 3 小时墙钟。若不能确认额度，不启动。
CPU 合成/小规模检查不代表 T4 显存验证或算法有效。正式成绩只能来自后续授权的比赛提交。
